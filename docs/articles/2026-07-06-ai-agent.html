AI Agent 入门：我用 n8n 搭了个自动选品工作流

做了二十年硬件，去年开始认真玩 AI，最大的感受是 —— Agent 不是"另一个工具"，是"一个新同事"。

它能替你盯数据、做初筛、发提醒。前提是你得告诉它：盯什么、怎么判、判完干啥。

需求：每天早上 8 点，告诉我"今天值得看的 3 个 AI 项目"

我每天扫 GitHub 找新冒头的 AI 项目，手动刷太累。让 Agent 替我做初筛，我只看它筛出来的结果。

思路拆解

  1. 触发：每天早上 8 点（cron）
  2. 采集：GitHub Search API，按关键词拉最近 7 天更新的 repo
  3. 过滤：去重 → 按 stars + 描述关键词打分 → 取 Top 5
  4. 推送：把结果写到飞书 Bitable + 发 DM 通知

为什么用 n8n

三个理由：

  • 可视化：节点拖拽连线，逻辑一目了然，方便回头改
  • 节点多：GitHub / 飞书 / HTTP / Cron 都是现成节点，不用写胶水代码
  • 本地能跑：不用上云，自己的机器上跑，数据不出门

完整工作流（12 个节点）

从左到右：

  1. Cron — 每天 8:00 触发
  2. Set — 配置关键词列表（AI agent / RAG / LLM / MCP ...）
  3. Loop — 对每个关键词循环
  4. HTTP Request — 调 GitHub Search API
  5. Code — 解析 JSON，提取关键字段
  6. Merge — 合并所有关键词的结果
  7. Code — 去重 + 打分
  8. Sort — 按分数倒序
  9. Limit — 取前 5
  10. HTTP Request — 写飞书 Bitable
  11. HTTP Request — 发飞书 DM
  12. IF — 失败重试一次

踩过的 3 个坑

1. GitHub API 限速

匿名 60/h，带 token 5000/h。装一个 PAT 放 n8n 的 credentials 里，立刻够了。

2. 飞书 Bitable 字段类型

日期字段是毫秒时间戳（不是字符串），URL 字段是 {"link": "...", "text": "..."} 这种结构体。看官方文档第一次没注意，调了半小时。

记忆：飞书 Bitable 的日期字段不接受 ISO 字符串，必须毫秒时间戳。

3. Cron 在容器里的怪事

我一开始用 terminal 工具跑，结果跨调用 /tmp 被清空，脚本找不到。换成单个 bash 块一次跑完，OK。

效果

跑了 3 周，每天早上 8 点准时推到飞书，3 条里有 1 条值得深挖，比手动刷效率高 10 倍。

下一步准备加 LLM 节点，让 Agent 直接给每个项目写一句话点评，省得我点开看 description。
